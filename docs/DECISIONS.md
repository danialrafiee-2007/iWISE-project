# Technical Decisions

Each decision records what was chosen and why, so any team member can defend it in the judges' Q&A.

| ID | Date | Decision | Reason |
|---|---|---|---|
| D-001 | 2026-10-21 | Challenge 4: Truth Guardian | Highest innovation and practical-value ceiling; few strong competitors |
| D-002 | 2026-10-21 | Core pipeline runs offline with open models; no paid LLM API in the core | Cost, reproducibility, privacy, and a clear answer to "is it just GPT?" LLMs only as a comparison baseline |
| D-003 | 2026-10-21 | English first; Persian is a stretch goal | Labeled data exists only in English |
| D-004 | 2026-10-21 | One JSONL schema (`Sample`) for every dataset | Converters, models, evaluation and the API share one contract |
| D-005 | 2026-10-21 | Splits by `meta.group_id`; a source never crosses train/dev/test | RAGTruth has 6 responses per source; random splits would leak |
| D-006 | 2026-10-21 | Final test split is created in week 2 and locked until week 11 | Prevents tuning on the test set |
| D-007 | 2026-10-21 | Training on Kaggle/Colab GPUs; local machine for CPU inference and the web app | Local GPU is a GeForce MX110 with 2 GB |
| D-008 | 2026-10-21 | Python 3.13 managed by uv, versions locked in `uv.lock` | Installed locally; uv could not install a separate 3.12 on this machine |
| D-009 | 2026-10-21 | Raw data pinned to exact repo commits with SHA-256 checks (`scripts/download_data.py`) | Every member gets byte-identical data; results are reproducible |
| D-010 | 2026-10-21 | RAGTruth official test split (2,700 responses) is the locked test set; dev is carved from train by `source_id` | Official split already keeps all 6 responses of a source together (0 sources cross splits) |
| D-011 | 2026-10-21 | RAGTruth "Conflict" maps to `contradicted`, "Baseless Info" to `unsupported`; original label kept in `source_label` | Matches our taxonomy without losing the original annotation |
| D-012 | 2026-10-21 | `implicit_true` spans (1,928) stay hallucinated | We measure faithfulness to the sources, not world truth |
| D-013 | 2026-10-21 | 173 responses with quality `incorrect_refusal` or `truncated` are excluded from training and reported separately | They are not normal answers and would add label noise |
| D-014 | 2026-10-21 | Every metric is reported per task as well as overall | Hallucination rate differs by task (test: QA 18%, Summary 23%, Data2txt 64%); a model could exploit task type |
| D-015 | 2026-10-21 | HaluEval used only for cross-dataset testing | Its QA, dialogue and summary hallucinations were deliberately generated, a different distribution from natural ones |
| D-016 | 2026-10-21 | Yelp structured data rendered as "key: value" lines (null as "not specified"), one document per review | NLI models are trained on natural text, not JSON; null values cause 1,642 labeled hallucinations, so they must stay visible |
| D-017 | 2026-10-21 | HaluEval: 500 question groups per task (1,000 samples), "general" excluded, all files locked | Enough for a cross-dataset check at a fraction of the compute; "general" has no source documents |
| D-018 | 2026-10-21 | Sentences: split on line breaks first, then spaCy's rule-based sentencizer, keeping character offsets | Structured data is one fact per line; offsets let us highlight the exact text in the UI |
| D-019 | 2026-10-21 | Confidence intervals by bootstrap over source groups, not single responses | The 6 responses of one source are correlated; per-response resampling would give falsely narrow intervals |
| D-020 | 2026-10-21 | Decision thresholds are tuned on dev only and passed to test unchanged | Tuning on test inflates results |
| D-021 | 2026-10-21 | Every F1 is reported next to the "flag everything" F1 | With 44% hallucinated responses, flagging everything already scores F1 0.615 on dev; AUROC is the fairer headline metric |
| D-022 | 2026-10-21 | Thresholds must be checked for transfer to test, and calibration is a core Phase 2 goal | Hallucination rate drops from 44.6% (train) to 34.9% (test), QA from 30.6% to 17.8% |
| D-023 | 2026-10-21 | Length is reported as a shortcut risk for HaluEval | HaluEval QA grounded answers average 2.3 words vs 11.1 for hallucinated ones |
| D-024 | 2026-10-21 | B3 premise = the 5 source sentences most similar to the answer sentence (in source order); score = 1 - P(entailment) | Sources exceed the 512-token NLI limit; 1 - P(entailment) flags both contradicted and unsupported sentences |
| D-025 | 2026-10-21 | NLI outputs are reordered by the model's own `id2label` | Different NLI models use different label orders (e.g. the large DeBERTa model we plan to try); hard-coded indices would silently break |
| D-026 | 2026-10-21 | ~~NLI over the training set runs on a Kaggle/Colab GPU in Phase 2~~ Superseded by D-033 | On the local CPU B3 takes about 5 s per response: about 2 hours for dev, about 19 hours for train |
| D-027 | 2026-10-21 | Symbolic checks favour precision: skip passage citations, word-count statements and generic date phrases; normalise US states and street abbreviations | On dev, word-level precision rose from 0.261 to 0.475 and sentence precision from 0.301 to 0.498, while response AUROC fell from 0.730 to 0.672. This signal's job is exact, explainable word-level evidence; ranking responses is the fusion model's job |
| D-028 | 2026-10-21 | Sentence labels = overlap with any gold span; spans are kept for word-level evaluation | In train, a hallucinated sentence has a median of 17 words but the gold span only 5 (median 45% coverage), so sentence-level highlighting alone caps span precision near 0.5; 7.2% of spans cross sentence boundaries |
| D-029 | 2026-10-21 | External dev = the next 250 HaluEval groups per task after the locked 500 (same ranking, disjoint) | Lets us check cross-dataset generalisation during development without touching locked files |
| D-030 | 2026-10-21 | Evidence retrieval = our own BM25 fused with embedding similarity by Reciprocal Rank Fusion (k=60) | Lexical matching beat embeddings on dev (B1 vs B2), so both rankings are combined; RRF needs no score calibration |
| D-031 | 2026-10-21 | HHEM loaded with `trust_remote_code` only at revision de9a5e6, after reading its code | Remote code runs on our machine; the reviewed revision only builds a T5 classifier and a prompt |
| D-032 | 2026-10-21 | LettuceDetect lives in a separate `study` dependency group and is never trusted on RAGTruth train/dev | It was trained on RAGTruth train, which includes our dev, so its dev scores are inflated and its train scores in-sample |
| D-034 | 2026-10-21 | Response scores must not be the plain max over sentence NLI scores; the fusion model learns the aggregation | B3 (NLI-base, max of 1 - P(entailment)) is the weakest baseline on dev: AUROC 0.631 vs B1 0.674 and B2 0.649. Its scores saturate (tuned threshold 0.9992) because almost every answer has some sentence NLI cannot confirm; on data2text it is near random (0.534) |
| D-035 | 2026-10-21 | Fusion = two-stage stacking: sentence classifier, then response classifier on aggregates of out-of-fold sentence probabilities and raw signals; one group-based fold assignment shared by both stages | Stage 2 must never learn from in-sample (over-confident) stage-1 scores; grouping by source prevents leakage |
| D-036 | 2026-10-21 | Classifiers: logistic regression vs scikit-learn HistGradientBoosting (same family as LightGBM) | No extra dependency; a simple, explainable model and a strong one are always compared |
| D-037 | 2026-10-21 | Calibration: Platt scaling fitted on out-of-fold response scores | Rank-preserving, so AUROC is unchanged; isotonic would create ties |
| D-038 | 2026-10-21 | Separate response and span (sentence) thresholds, both tuned on dev; threshold grid uses observed scores only | Sentence probabilities and calibrated response probabilities are on different scales |
| D-039 | 2026-10-21 | Saved models: models/fusion/<version>/ with model.joblib, a manifest (signal versions, data, metrics, thresholds, SHA-256) and a LATEST pointer; loading refuses tampered files and stale signal versions | Fast reuse for the team and judges without silent mismatches; joblib files can run code, so integrity is checked |
| D-040 | 2026-10-21 | Results are marked "dirty" only when src, scripts or dependencies differ from HEAD | Result files changing during long runs should not mark reproducible code as dirty |
| D-041 | 2026-10-21 | NLI-large dropped | Measured about 600 s per sample on the laptop (memory pressure with other jobs), about 43 hours for the 306-sample study subset alone |
| D-042 | 2026-10-21 | Fusion candidates: lexical, symbolic, dense, NLI-base, HHEM. LettuceDetect stays out of the fusion and is reported only as an external reference on the locked test | Signal study (306 RAGTruth dev / 300 HaluEval xdev): HHEM is the best clean signal (0.795 / 0.684). LettuceDetect's 0.966 on RAGTruth dev against 0.661 on HaluEval confirms the contamination from D-032 |
| D-043 | 2026-10-21 | Structure features (position, sentence length, sentence count) are kept but always reported with an ablation | Cheap fusion (lexical + symbolic, HGB) reaches dev AUROC 0.835 against B1's 0.674, and 0.813 without structure. Gains hold within every task and every generator (e.g. llama-2-13b 0.541 to 0.851), so they are not task or generator identity |
| D-044 | 2026-10-21 | Heavy signals (NLI, HHEM) are first extracted on 170 train groups (~1,000 responses); more groups only if the learning curve and ablation show they pay off | About 8 s per response on the laptop; full train would take about 30 hours |
| D-045 | 2026-10-21 | Fix-it: no LLM; the replacement comes from the source sentence closest to the claim (BM25, ignoring the wrong item), matched by number type and context, range role (opens/closes), or entity label | Explainable and offline. On train vs annotator notes it is right 68% of the time (lower bound; Data2txt 74%), but it covers only 58 of 1,199 contradictions because most contradictions are about meaning, not numbers or names |
| D-046 | 2026-10-21 | RAGTruth annotator notes ("Original: ...") kept as `Span.note` | They are the only reference for what the source really said; used to score Fix-it |
| D-047 | 2026-10-21 | "Fool the Guardian" suite: 60 grounded dev answers (20 per task, one per source), each edited once per kind (number, entity, negation, antonym, addition), plus the 60 originals as controls; never used for training or thresholds | Exact gold spans and originals per edit; tests the blind spots of each signal. With cheap signals only, negation and antonym edits are missed (AUROC about 0.52), which the semantic signals must fix |
| D-048 | 2026-10-21 | The data story uses RAGTruth train + dev only, with group-bootstrap intervals | The locked test stays untouched; numbers describe 2023-era models and are presented as such |
| D-049 | 2026-10-21 | NLI-base removed from the final signal set | With 1,009 training samples, dropping NLI leaves dev AUROC unchanged (0.832 vs 0.831) and raises out-of-fold AUROC (0.801 to 0.818), while it costs about 4.6 s per response; dropping HHEM instead costs 0.013 on dev and up to 0.12 on HaluEval QA |
| D-050 | 2026-10-21 | HHEM extended to 1,360 train groups (about 8,000 responses) | Cheap-fusion learning curve on dev: 1k 0.807, 2k 0.816, 4k 0.824, 8k 0.838, 13.4k 0.839, so gains plateau near 8,000 |
| D-051 | 2026-10-21 | Model selection weighs HaluEval external dev, not only RAGTruth dev | The challenge asks for reliability "on new examples"; structure features and boosting raise RAGTruth dev slightly but lower HaluEval AUROC (e.g. logistic regression without structure: QA 0.874, dialogue 0.674, summary 0.680) |
| D-052 | 2026-10-21 | Images and audio are out of scope for the competition build | The official Challenge 4 text is text-only (zero mentions of image, audio, video or multimodal) and rules require staying within the selected challenge; voice input may be added as UI only, multimodal goes to the future-work slide; scope question added to the organiser email |
| D-053 | 2026-10-21 | AgentHallu inputs are only question, agent steps and final answer; `true_answer` and `explanation` are dropped at conversion (a unit test checks they never appear) | They are the dataset's answer key and solution notes; using them would be cheating |
| D-054 | 2026-10-21 | AgentHallu split by question: one third dev (231 trajectories), two thirds locked test (462) | Tracer rules and weights are developed on dev only; all 7 agent frameworks appear on both sides |
| D-055 | 2026-10-21 | Tool outputs become the documents; a trajectory step keeps its tool output as `observation`; repeated step numbers (one BFCL file) are merged | Tool outputs are the evidence an agent's claims should rest on; merging keeps the annotated step numbers valid |
| D-056 | 2026-10-21 | Provenance tracer v0: time rule (step k may only rely on the question and earlier tool outputs), scoring unsupported numbers/names, their spread to the final answer, tool errors and content novelty; hand-set weights, ties to the earliest step | Transparent, CPU-light and explainable per step; weights get learned on dev in Phase 3. Must beat "always step 1" (25% of AgentHallu labels) and the paper's best of 41.1% |
| D-057 | 2026-10-21 | Known limitation: race-time values like "1:39.87" are split into "1:39" and "87" by the shared number pattern | Both parts are still flagged as unsupported; changing the pattern would invalidate cached symbolic features, so it waits for the next symbolic version |
| D-058 | 2026-10-21 | Tracer v0 is a baseline, not the final tracer; Phase 3 learns step weights on AgentHallu dev with question-grouped cross-validation | On dev (140 hallucinated trajectories) v0 finds the exact step 29% of the time (always-step-1 27%, random 17%), within one step 50%, top-3 68%; strong on tool use (30% vs 6%) and reasoning (31% vs 11%), but 0% on retrieval and below the step-1 prior on planning (64% vs 96%); detection AUROC 0.557; 15 s per trajectory under CPU load |
| D-059 | 2026-10-21 | Semantic signals are judged on the Fool-the-Guardian suite as well as RAGTruth | With logistic regression and no structure, adding HHEM lifts negation detection from AUROC 0.50 to 0.61 and additions to 0.90; adding NLI lifts negation further to 0.69, a gain invisible on RAGTruth dev; negation and opposite-word edits remain the weakest case |
| D-060 | 2026-10-22 | Polarity check: the rule proposes (near-restatement with flipped negation or a WordNet antonym), NLI confirms (contradiction >= 0.8) on just that sentence pair; applied as an override after the fusion model | Rules alone had precision 0.03-0.08 on natural train answers (below the 0.11 base rate). Settings chosen on train only: the loosest rule (overlap >= 0.65, length ratio <= 2.5) with zero added natural false alarms on 1,188 train answers. Suite negation detection 38% to 71% (AUROC 0.62 to 0.78), RAGTruth dev unchanged within noise; NLI runs on about 2% of sentences instead of all |
| D-061 | 2026-10-22 | Report contract: per claim status (supported, contradicted, unsupported, insufficient_evidence), risk, type, word spans, evidence with its document, explanation, action (keep, replace, remove, verify) and Fix-it replacements; per answer verdict grounded, hallucinated or uncertain | One contract for web app, API and batch; "insufficient evidence" and "uncertain" (risk within 0.1 of the threshold, or only weak-evidence claims) avoid forcing a verdict |
| D-062 | 2026-10-22 | Live pipeline computes every signal on the fly for any input; cached features are only for training and evaluation | The web app and judges' inputs never exist in the cache |
| D-063 | 2026-10-22 | Tracer evidence kept in an incremental index; NER only on the first 5,000 characters of a step and only when it contains capitalised words | 15 s to 0.16 s per trajectory with the same tests passing |
| D-064 | 2026-10-22 | Learned tracer: logistic regressions over 13 step features (step origin) and their max/mean (trajectory risk), trained on AgentHallu dev | Out-of-fold on dev: exact step 38% (v0 28%, step-1 prior 27%, random 17%), top-3 79%; reasoning 49%, human interaction 62%; still weak on retrieval (10%) and trajectory detection (AUROC 0.54). The paper's best, 41.1% with large LLMs, is on a different evaluation set, so it is a reference, not a like-for-like comparison |
| D-065 | 2026-10-22 | After the first setup, everything runs offline (`uv run --offline`, `HF_HUB_OFFLINE=1`) | A network timeout on the spaCy model URL stopped two evaluation runs; on judging day nothing may depend on the internet |
| D-066 | 2026-10-22 | Final brain: ensemble (logistic regression + boosting) on lexical, symbolic, dense and HHEM signals, no structure features, polarity override; saved as models/fusion/20261022-001651-ensemble | On 8,089 train samples it has the best cross-validation (0.842), RAGTruth dev 0.844 (boosting 0.847, logistic 0.822), the best HaluEval average (0.766: QA 0.920, dialogue 0.674, summary 0.703) and no weak column on the Fool-the-Guardian suite |
| D-067 | 2026-10-22 | Milestone M2 passed; Phase 2 closed | Dev AUROC 0.844 [0.824, 0.861] vs B1 0.674 [0.648, 0.699] and B3 0.631 [0.600, 0.660] (no overlap); span F1 0.383 vs 0.207; ECE 0.038; every task improves (data2text 0.557 to 0.832, QA 0.683 to 0.863, summary 0.633 to 0.722); the saved model loads in about 7 s including library imports |
| D-068 | 2026-10-22 | Tracer origin = the step that first states an unsupported value; later steps repeating it are not blamed | A test showed the final answer being blamed for repeating step 2's value. Out-of-fold exact step on AgentHallu dev rose from 38% to 40% (reasoning 49% to 54%) |
| D-069 | 2026-10-22 | HHEM-based semantic step features kept optional, not in the final tracer | Gain within noise (exact 41% vs 40%, +-1 55% vs 50%, detection 0.574 vs 0.559 on 140 trajectories) for several seconds per trajectory |
| D-070 | 2026-10-22 | TG-Agent: 220 scripted trajectories from grounded RAGTruth dev QA answers (60 clean; one injected error each: 40 fabricated fact at step 3, 60 ignored tool error at step 3, 60 answer addition at step 4); a controlled test, never trained on | Exact origins by construction; also the demo presets for the agent timeline |
| D-071 | 2026-10-22 | Final tracer: content-only (no position or step-kind features) learned model mixed 50/50 with the v0 evidence score; chosen by best worst case over AgentHallu and TG-Agent | Learned-with-position memorised AgentHallu habits (step 1 often blamed, last step rarely) and fell to 2% exact on TG-Agent. Exact step: v0 31% / 53%, learned 40% / 2%, final 37% / 39% (worst case 37%, best of all); within one step 56% / 84%; 0.03 s per trajectory. The two datasets also differ in convention: AgentHallu blames the failing tool call, TG-Agent the step that then makes the false claim |
| D-072 | 2026-10-22 | Human evaluation replaces TG-Agent annotation: two team members independently judge 63 flagged claims from 40 dev answers (flag correct, type correct, explanation helpful 1-5); Cohen's kappa and human-judged precision via `scripts/annotation_kit.py` | TG-Agent labels are exact by construction; human judgement is most informative on the system's explanations. The export also exposed weak name replacements in Fix-it, now guarded (must share half of the claim's other words): Fix-it accuracy vs notes 68% to 73% |
| D-073 | 2026-10-22 | Milestone M3 passed; Phase 3 closed (locked AgentHallu test untouched) | Tracer beats always-step-1 and random on real trajectories (37% vs 27% / 17%) and on controlled ones (39% vs 0% / 25%; within one step 84%); agent timeline in the report and live pipeline; known limits: retrieval hallucinations (6%) and trajectory-level detection on natural data (AUROC 0.57) |
| D-033 | 2026-10-21 | All computation runs on the local laptop; heavy signals are cached per sentence and extraction resumes after interruption | User requirement; caching turns re-training and evaluation into seconds |
